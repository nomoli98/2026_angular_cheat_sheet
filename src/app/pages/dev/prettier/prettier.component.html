Prettier (code formatting)

Prettier rewrites your files so they all look the same: quotes, indentation, line length, commas. You stop arguing about style and stop fixing it by hand. In this repo it runs on every file when you start npm run dev. Full guide: PRETTIER.md · Prettier docs.

How it works

  • Prettier throws away your formatting and prints the code again from scratch, following .prettierrc. Same code in → same layout out, whoever wrote it.
  • It only changes how the code looks, never what it does. It formats .ts, .html, .css, .json and .md (including the code blocks inside the snippets).
  • npm run dev first runs predev: npm automatically runs a script called pre<name> before <name>. That's where prettier --write . sits, so the whole repo is formatted before the API and ng serve start.

1. Install

A dev dependency: it's only used while you write code, not in the built app.

2. Configure it

  • tabWidth: 4 + useTabs: false → indent with 4 spaces.
  • singleQuote: true → 'text' instead of "text" in TS. JSON and HTML attributes keep double quotes: that's their syntax.
  • printWidth: 100 → lines are wrapped after 100 characters.
  • The *.html override uses the angular parser, so it understands @if, @for, [prop], (event).

Set the same indentation in .editorconfig, so your editor types 4 spaces too and Prettier has nothing to fix.

3. Tell it what to skip

.prettierignore works like .gitignore. Skip generated files and fake-api/db.json: json-server rewrites it with its own formatting on every change.

4. Add the scripts

  • --write changes the files, --check only lists the ones that aren't formatted (and fails, handy in CI).
  • . = every file in the project, minus .prettierignore.
  • --log-level warn in predev: don't print every file, only problems.

6. (Optional) Format on save in VS Code

Install the Prettier extension. It reads the same .prettierrc, so saving a file gives the same result as npm run format.

Gotchas

  • Changed the config? Run npm run format once: Prettier doesn't touch files until it runs.
  • A file with a syntax error can't be formatted: Prettier prints the error and leaves it as it is.
  • Want Prettier to leave one block alone? Put // prettier-ignore (or <!-- prettier-ignore --> in HTML) on the line before it.
  • Reformatting the whole repo touches almost every file: commit it on its own, so real changes stay easy to read in the history.
