Tokens (JWT): how it works

With the plain and bcrypt versions, "logged in" is a signal in the browser: the server never knows who you are, and a refresh forgets you. With a token, the server gives you a signed proof after login. You send it back with every request, the server checks it. 

1. POST /token/login  {{ '{' }} email, password {{ '}' }}   → server: bcrypt.compare → signs a JWT
2. Angular keeps it          localStorage  (still logged in after a refresh)
3. GET /token/me             Authorization: Bearer <token>   (added by tokenInterceptor)
4. server: jwt.verify()      signature OK + not expired → 200, otherwise 401

Built on bcrypt, but the hashing is now on the server (fake-api/auth-server.js, port 3001), like a real API. Pages: Register (token) · Login (token). Needs npm run dev.
