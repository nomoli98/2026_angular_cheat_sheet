bcrypt: how it works

Storing passwords as plain text means anybody who reads the database (a leak, a backup, a curious admin) gets every password. bcrypt stores a hash instead: a one-way fingerprint. You can't turn it back into the password, you can only check if a password gives the same hash.

  • Salt: random characters mixed in, saved inside the hash. Same password → a different hash every time, so two users with the same password don't look the same.
  • Cost: bcrypt is slow on purpose. 100 ms is nothing for a login, but it makes guessing billions of passwords impossible.
