Authentication = who are you? (login, token: see Auth service and Tokens). Authorization = now that I know who you are, are you allowed? In this repo the answer depends on the user's role: admin or user.

Where What it does Real security?
Template (@if, [disabled]) hides / disables what you can't do ❌ comfort only
Component method doesn't call the controller when it's a no ❌ comfort only
Route guard (adminGuard) doesn't open the page ❌ comfort only
Controller (isAdmin + deny) one place for the rules, the app can't skip it ❌ still in the browser
Server checks the token + role on every request ✅ the only real one

Everything in the browser can be changed by the user (DevTools, curl...). The front-end checks are for a good UX and fewer useless requests. The server must check again.

4. Protect a whole page: adminGuard

authGuard asks are you logged in?. adminGuard asks are you an admin?. A simple user who opens the page is sent back here with ?forbidden=.... Switch Admin off while on the admin page: the toggle re-runs the guards and you get kicked out.
