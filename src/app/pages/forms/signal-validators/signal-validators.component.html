Signal Forms · Validators

Every rule is one line in the schema function, and each error carries its message. Type in the fields: the kinds line shows what Angular sees. Full guide: SIGNAL_VALIDATORS.md.

1. Built-in rules

required, minLength, maxLength, min, max, email, pattern. Path first, then {{ '{' }} message {{ '}' }}. On a boolean, required means "must be true".

@let name = builtInForm.name();
@if (name.touched()) { @for (error of name.errors(); track error.kind) {
{{ error.message }}
} }
kinds: [@for (e of name.errors(); track e.kind) { {{ e.kind }} }]

2. Custom rule

A function that calls validate(path, ctx => ...). Return undefined = valid, or one / several {{ '{' }} kind, message {{ '}' }}. Add a second argument for parameters: birthdate(field.birthdate, {{ '{' }} minAge: 18 {{ '}' }}).

@let password = customForm.password();
@if (password.touched()) { @for (error of password.errors(); track error.kind) {

3. Cross-field rule

Read the other field with valueOf(otherPath). The rule re-runs when either field changes, and the error lands on confirmPassword itself (no group like in reactive forms).

@let confirm = crossForm.confirmPassword();

4. Async rule

validateHttp() takes a request (URL + params), not an Observable. It only runs when the sync rules pass, and pending() is true while it waits. Needs the fake API (npm run dev). Try bob@email.bob.

} @if (mail.touched()) { @for (error of mail.errors(); track error.kind) {
{{ error.message }}
